# 项目开发记录

S32K144 位移传感器 5 kHz 采集系统。本文档记录开发过程中的关键技术决策、遇到的问题及解决方案。

---

## 1. 项目概述

| 项目 | 内容 |
|---|---|
| MCU | NXP S32K144，Cortex-M4，FIRC 48 MHz |
| 开发环境 | S32 Design Studio + ARM GCC 6.3 |
| 功能 | 4–20 mA 位移传感器 → 5 kHz ADC 采样 → 串口文本输出 |
| 输出 | ASCII 十进制，单位 0.1 mm，每行一点，CRLF |
| 串口 | LPUART1，921600，8N1，无流控 |

---

## 2. 硬件信号链

```text
位移传感器（三线制，4–20 mA 恒流输出）
    ↓
串联采样电阻 R（I-V 转换）
    ↓
PTB3 / ADC0_SE7 对 GND 电压 = I × R
    ↓
S32K144 ADC0，12 位，0–3.3 V 参考
```

### 完整电路连接关系

#### 接线表

| 传感器线色 | 连接到 | 说明 |
|---|---|---|
| 红线（V+） | 外部电源正极 +12～24 V | 传感器供电，**不接**单片机 3.3 V |
| 黑线（0V） | 外部电源负极 | 同时必须与开发板 GND 共地 |
| 灰线（IOUT） | PTB3（ADC0_SE7） | 4–20 mA 恒流输出 |

#### 电路拓扑

```text
外部电源 +12~24 V
        │
        ├──────────────────────► 传感器红线 V+
        │
   ┌────┴─────┐
   │ 位移传感器 │  三线制，4–20 mA 恒流输出
   └────┬─────┘
        │ 灰线 IOUT（4~20 mA 恒流）
        │
        ├──────────► PTB3 / ADC0_SE7（S32K144 ADC 输入，高阻）
        │
        │          ← 关键：必须有这个对地电阻
     ┌──┴──┐
     │ R   │  100 Ω，0.1% 精密电阻（I-V 转换 / 采样电阻 / shunt）
     └──┬──┘
        │
        ├──────────► 开发板 GND
        │
外部电源 0 V（负极）───┴──────► 共地（必须与开发板 GND 同一节点）
```

#### 三个关键连接要点

**1️⃣ 100 Ω 必须从 PTB3 节点接到 GND**

```text
正确：PTB3 ──[100Ω]── GND
错误：PTB3 ────────── 灰线（悬空，电阻缺失）
```

4–20 mA 是**恒流源**。若采样电阻缺失，电流无处流走，PTB3 电压会被顶到传感器的顺从电压上限（实测约 4.2 V），远超 ADC 量程，且会超过 STM32/S32K 引脚的绝对最大额定值（VDD+0.3 V ≈ 3.6 V），有损坏风险。

**2️⃣ 外部电源负极必须与开发板 GND 共地**

若两者不共地，PTB3 的参考地与 ADC 的参考地不一致，采样节点会浮空，读数随机或满量程。

**3️⃣ 传感器的供电不要取自开发板 3.3 V**

4–20 mA 变送器通常需要 12–24 V 才能驱动环路，3.3 V 供电会导致输出电流无法达到 20 mA。

#### 电压换算关系

```text
V_PTB3 = I × R = (4~20 mA) × 100 Ω = 0.4 ~ 2.0 V
```

| 位移 | 环路电流 | PTB3 电压 | ADC 码（12 位，3.3 V 参考） |
|---|---|---|---|
| 0 mm | 4 mA | 0.40 V | ≈ 496 |
| 375 mm | 8 mA | 0.80 V | ≈ 993 |
| 750 mm | 12 mA | 1.20 V | ≈ 1489 |
| 1125 mm | 16 mA | 1.60 V | ≈ 1986 |
| 1500 mm | 20 mA | 2.00 V | ≈ 2482 |

#### 引脚配置

```c
/* Sources/displacement.c — Displacement_Init() */
const pin_settings_config_t adcPin = {
    .base = PORTB,
    .pinPortIdx = 3U,          /* PTB3 */
    .mux = PORT_PIN_DISABLED,  /* MUX=0 → 关闭数字功能，切到模拟输入 */
    .gpioBase = NULL,
};
PINS_DRV_Init(1U, &adcPin);
```

**MUX=0 的含义**：S32K 的 PORTx_PCRn 寄存器：

| MUX 值 | 功能 |
|---|---|
| 000 | **模拟（Analog）**，数字输入输出缓冲器断开，只连 ADC |
| 001 | GPIO |
| 010 / 011 | 外设复用（UART / SPI / PWM…） |

必须设为 000，否则数字输入缓冲器会加载模拟信号，导致读数偏差。

### 关键参数

| 参数 | 值 | 说明 |
|---|---|---|
| 传感器输出 | 4–20 mA | 对应 0–1500 mm |
| 采样电阻 | 100 Ω（标称） | 实测推算约 92 Ω，疑似 91 Ω |
| ADC 参考 | 3.3 V | 4096 级 |
| 量化步长 | 0.806 mV/码 | 3.3 V / 4096 |
| 理论电压范围 | 0.4–2.0 V | 仅占 ADC 量程约 48% |

### 重要修正：量程利用率

初版理解把 0.4–2.0 V 当作占满 4096 级，这是错误的。实际：

```text
0.4 V → 496 码
2.0 V → 2482 码
可用码数 = 1986
理论分辨率 = 1500 mm / 1986 = 0.755 mm/码
```

所以代码显示的 0.1 mm 只是**显示精度**，真实分辨率是 0.755 mm/码。

## 3. 5 kHz 采样的实现：PDB 硬件触发

### 核心机制

不是软件延时，也不是定时中断，而是 **PDB（Programmable Delay Block）纯硬件定时**：

```text
CORE_CLK 48 MHz
    ↓ PDB0 计数器 CNT: 0 → 9599（9600 个周期）
    ↓ 每 200 μs 产生一个硬件触发脉冲
ADC0 收到触发，开始 12 位转换
    ↓ 转换完成
ADC0_IRQn 中断 → AdcComplete() 读取结果
```

CPU 只在最后的中断里出现，定时和触发链路全在硬件中闭环。

### 关键寄存器配置

```c
PCC->PCCn[PCC_PDB0_INDEX] |= PCC_PCCn_CGC_MASK;   /* 打开 PDB 时钟 */

PDB0->MOD  = 9600 - 1;      /* 模值 9599，计数器 0..9599 共 9600 拍 */
PDB0->IDLY = 9600 - 1;
PDB0->CH[0].C1 = PDB_C1_EN(1) | PDB_C1_TOS(1);    /* 使能 pretrigger 0，直通输出 */
PDB0->CH[0].DLY[0] = 1;
PDB0->SC = PDB_SC_TRGSEL(15)                      /* 软件触发源 */
         | PDB_SC_CONT_MASK                       /* 连续模式 */
         | PDB_SC_PDBEIE_MASK                     /* 序列错误中断 */
         | PDB_SC_PDBEN_MASK
         | PDB_SC_LDOK_MASK;                      /* 允许加载影子寄存器 */
PDB0->SC |= PDB_SC_SWTRIG_MASK;                   /* 软件启动第一拍 */
```

**为什么 MOD 写 9599 而不是 9600**：计数器从 0 开始，`0..9599` 正好 9600 个周期。写 9600 会变成 9601 拍。

**LDOK 的作用**：`MOD`/`IDLY`/`DLY` 是双缓冲寄存器，写入后必须置 LDOK 才在周期边界整体生效，避免运行中改周期产生毛刺。

### 为什么不用其他方式

| 方式 | 抖动 | 结论 |
|---|---|---|
| 软件 `while` 延时 | 几十 μs | 不可用 |
| LPIT 定时中断里软件触发 | 1–3 μs | 5 kHz 下抖动约 1% |
| **PDB 硬件触发** | 仅晶振抖动 | **采用** |
| ADC 连续转换模式 | 速率不可控 | 无法精确设 200 μs |

### 实测验证

```text
采样率     5002 Hz
数据速率   10004 字节/秒（二进制版本，每点 2 字节）
```

## 4. 软件架构：两级生产者-消费者

```text
ADC 中断（生产者，5000 Hz）
    ↓ raw 写入
samples[2048] 环形缓冲
    ↓ 主循环（消费者），攒满 64 点
换算 + 格式化
    ↓ packet[] 非阻塞发送
LPUART1 中断（逐字节输出）
```

### 环形缓冲设计

```c
static volatile uint16_t samples[2048];
static volatile uint32_t produced, consumed;

/* 生产者（中断） */
samples[produced & 2047] = raw;
DISPLACEMENT_BARRIER();      /* dmb */
produced++;

/* 消费者（主循环） */
first = consumed;
if ((produced - first) < 64) return;   /* 不足一块，等待 */
...
consumed = first + count;
```

关键点：

1. **`& 2047` 代替 `% 2048`** —— 缓冲区大小必须是 2 的幂，位与只需 1 个周期
2. **`volatile`** —— 中断改、主循环读，防止编译器缓存到寄存器
3. **`dmb` 内存屏障** —— `volatile` 只保证读写真实发生，**不保证顺序**。必须保证「写数据」在「更新指针」之前，否则消费者可能看到新指针但读到旧数据
4. **无符号减法** —— `produced - consumed` 即使 `produced` 溢出归零也能得到正确差值（模 2³² 运算），不能用有符号比较
5. **单生产者单消费者无需关中断** —— 两个指针各由一方独占写

### 缓冲区容量

```text
2048 点 / 5000 Hz = 409.6 ms
```

主循环最坏情况被阻塞 400 ms 也不丢数据，实际只需 1–2 ms，余量充足。

### 为什么 64 点成块发送

| 方式 | 每秒 UART 中断次数 |
|---|---|
| 每点单发 | 5000 |
| 64 点成块 | 78 |

中断频率降低 64 倍，CPU 负载大幅下降。

### 为什么 `packet[]` 要用 `transmitting` 标志保护

`packet[]` 是全局共享。若上一次发送未完成就写入新数据，串口会输出「一半旧数据 + 一半新数据」的乱码。

```c
if (transmitting) {
    status = LPUART_DRV_GetTransmitStatus(INST_LPUART1, NULL);
    if (status == STATUS_BUSY) return;   /* 还没发完，本次不处理 */
    transmitting = false;
    ...
}
```

## 5. 中断优先级设计

```c
INT_SYS_SetPriority(ADC0_IRQn, 0U);            /* 最高，200 μs 必须响应 */
INT_SYS_SetPriority(LPUART1_RxTx_IRQn, 2U);    /* 较低，慢一点无妨 */
```

原则：**周期越短、实时性要求越高，优先级越高**。

### 中断里为什么不做浮点换算

```text
float 运算 → 需要保存浮点寄存器上下文 → 中断延迟增大
→ 200 μs 采样周期可能来不及 → 丢点
```

中断只做「读结果 + 存缓冲区」，所有换算和格式化都在主循环。

## 6. 故障码设计

| 码 | 含义 |
|---|---|
| 3 | 环形缓冲溢出（主循环太慢） |
| 4 | PDB 序列错误（ADC 未及时响应触发） |
| 5 | ADC 停止更新（100 ms 内 produced 无变化） |
| 6 | UART 发送失败 |

```c
/* 软件看门狗：100 ms 内应该有 500 个点 */
if (produced != lastProduced) {
    lastProduced = produced;
    lastProgressMs = now;
} else if ((now - lastProgressMs) > 100U) {
    StopWithFault(5U);
}
```

## 7. 换算与标定

### 初版公式（有问题）

```c
voltage   = raw * 3.3f / 4095.0f;
currentMa = voltage * 1000.0f / 100.0f;
position  = (currentMa - 4.0f) / 16.0f * 1500.0f;
```

### 问题：拉 10 cm 读到 79 mm，偏差 19%

实测数据：

| 真实位置 | 读数均值 | 读数中位数 |
|---|---|---|
| 100 mm | 80.9 mm | 79.1 mm |
| 400 mm | 351.0 mm | 356.3 mm |

反推 ADC 码：100 mm → 601，400 mm → 968。

拟合直线：

```text
斜率 = (968 - 601) / 300 = 1.223 码/mm
理想 = (2482 - 496) / 1500 = 1.324 码/mm
实际灵敏度只有理想的 92.4%
```

**根因分析**：

- 增益偏低 7.6% → 采样电阻可能是 **91 Ω** 而非 100 Ω（92.4 Ω 推算值接近 E24 标准值 91 Ω）
- 零点偏移 18 码 → 传感器零点电流略低于 4 mA

**为什么 4% 的 ADC 偏差会放大成 19% 的位移偏差**：

```text
4 mA 基线 = raw 496
100 mm 对应 raw 629
有效码数 = 133
实测 raw 603，有效码数 = 107
107 / 133 = 80.5%
```

4–20 mA 传感器的基线抬高了测量台阶，任何基线误差被放大约 15 倍（1986/133）。

### 改进：两点端点标定

`Sources/displacement.h`：

```c
#define DISPLACEMENT_RAW_ZERO     478   /* 0 mm 对应的 ADC 码 */
#define DISPLACEMENT_RAW_FULL     2313  /* 1500 mm 对应的 ADC 码 */
```

`Sources/displacement.c`：

```c
den = RAW_FULL - RAW_ZERO;
num = (raw - RAW_ZERO) * 15000;
positionTenthMm = (num >= 0) ? (num + den/2)/den : (num - den/2)/den;
```

优点：

- 直接标定 ADC 码，绕过电阻、VREF、传感器零点的所有累积误差
- 整数运算，避免浮点舍入
- 术语：**端点标定（end-point calibration）**

### 标定结果验证

| 真实位置 | 标定后读数 | 误差 |
|---|---|---|
| 300 mm | 300.27 mm | **+0.27 mm（0.09%）** |

系统误差基本消除。

## 8. 噪声问题

### 实测噪声水平

| 位置 | 标准差 |
|---|---|
| 100 mm | 6.7 mm |
| 300 mm | 6.2 mm |
| 400 mm | 11.6 mm |

单点分辨率 0.755 mm/码，但噪声约 ±8 码，**噪声主导精度**。

### 可能来源

1. 4–20 mA 环路干扰（信号线与电源线并行）
2. PTB3 输入端无 RC 滤波
3. 采样电阻引线过长，寄生电感
4. 单点输出无平均

### 改进方向（未实施）

**软件滑动平均**：

| N | 噪声 | 延迟 |
|---|---|---|
| 4 | ±3.1 mm | 0.6 ms |
| 16 | ±1.5 mm | 3.2 ms |
| 64 | ±0.8 mm | 12.8 ms |

**硬件 RC 低通**：

```text
        1 kΩ
PTB3 ──/\/\/──┬──────── ADC0_SE7
              │
           ┌──┴──┐
           │100nF│
           └──┬──┘
              │
             GND
```

截止频率 `f = 1/(2π × 1000 × 100n) ≈ 1.59 kHz`，适合 5 kHz 采样的抗混叠。

## 9. 温度功能（已停用）

MAX31865 + 三线 PT100 代码保留在工程中，但**当前未被调用**。

### 曾经的实现

```c
#define TEMPERATURE_PERIOD_US 1000000U
LPIT_Init(TEMPERATURE_PERIOD_US);       /* LPIT 1 秒周期，轮询方式 */
while (1) {
    if (LPIT_HasElapsed()) {
        MAX31865_ReadTemperature(&measurement);
        ...
    }
}
```

`isInterruptEnabled = false` —— 主循环轮询标志位，不用中断。

### 三种定时器对比

| 用途 | 定时器 | 周期 | 方式 |
|---|---|---|---|
| 位移采样 | PDB | 200 μs | 硬件触发 ADC |
| 温度周期 | LPIT | 1 s | 主循环轮询 |
| 转换等待 | SysTick | 70 ms | 阻塞延时 |

选择原则：**精度要求越高，定时越往硬件下沉；要求低则软件轮询更简单。**

### MAX31865 的速率上限

| 滤波设置 | 转换时间 | 最大采样率 |
|---|---|---|
| 50 Hz | 21 ms | ≈ 47.6 Hz |
| 60 Hz | 16.7 ms | ≈ 60 Hz |

**物理上不可能达到 5 kHz**，差约 100 倍。Σ-Δ ADC 的采样率由内部数字滤波器决定，提高 SPI 时钟无效。

## 10. 调试过程中解决的关键问题

### 问题 1：串口数据看起来是乱码

**现象**：满屏 `?\0`、`\0`

**原因**：二进制 int16 数据被串口助手当文本显示。`0x05 0x00` 显示为 `?` 和 `\0`。

**验证**：用 Python 脚本按 `<64h` 解码，数据完全正确。

**结论**：不是数据错误，是显示模式问题。

### 问题 2：ADC 一直满量程 4095

**现象**：`raw=4095`，PTB3 实测电压 4.2 V

**原因**：**采样电阻未接到 GND**。4–20 mA 恒流源接在高阻输入上，电流无处流走，电压被顶到传感器的顺从电压上限（约 4 V）。

**风险**：S32K144 引脚绝对最大额定 VDD+0.3 V ≈ 3.6 V，4.2 V 已超限，可能损伤引脚。

**解决**：补上 100 Ω 到 GND，电压恢复正常。

### 问题 3：MAX31865 报 error=3 fault=0x40 rtdreg=0x0001

**现象**：配置寄存器读回正常（`meascfg=0xD1`），但 RTD 原始值只有故障位

**排查过程**：

1. 拆分 RTD 两字节连续读为两个单字节事务 —— 无效
2. 改为连续转换模式 `0xD3`（参考实际可用代码）—— 配置正确但仍为 0
3. 把 SPI 时钟极性从空闲低改为空闲高 —— 仍为 0

**结论**：`0xD1` 证明配置写入正确，SPI 通信正常。`rtdreg=0x0001` 是芯片真实返回，说明模拟输入端存在问题，不是软件。

### 问题 4：`clean` 删除了构建文件

**原因**：`Debug_FLASH` 里的 `makefile`、`Sources/*.args` 是 S32DS 生成的构建输入，`make clean` 会把它们一并删除。

**教训**：**不要对 S32DS 工程执行 `make clean`**，应在 S32DS IDE 里用 Project → Clean。

**恢复**：手工补了一个最小 `Debug_FLASH/makefile`，用通配符收集源码和 SDK。
